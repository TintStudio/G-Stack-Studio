Security & OAuth Architecture

G-Stack Studio is engineered as an offline-first Windows desktop client application. We believe agencies should retain 100% control over their Google API keys, client content, and third-party cloud hosting credentials.

1. Local Execution Architecture

Unlike traditional multi-tenant cloud SaaS platforms, G-Stack Studio executes directly on your Windows PC. The software runs locally and communicates with third-party platforms via official, encrypted HTTPS REST APIs:

Your Computer (Local Client)

Houses project files (projects.json), client NAP profiles, image assets, AI prompt templates, and OAuth credentials.

Direct API Communication

Direct TLS 1.3 encrypted HTTPS requests between your desktop and Google APIs, AWS S3, Cloudflare, Netlify, and Vercel.

The only external server communication made by the desktop software to G-Stack Studio infrastructure is a periodic licensing heartbeat ping to our Google Apps Script license verification endpoint, which checks license activation status, machine hardware ID (HWID), and plan quota limits.

2. Google OAuth 2.0 & Token Handling

G-Stack Studio utilizes Google's standard Desktop InstalledAppFlow:

  • Bring-Your-Own-Client: You create an OAuth 2.0 Desktop Client in your own Google Cloud Console. This provides private API quotas and avoids Google's 100-test-user restriction.
  • Local Loopback Authorization: During authentication, Google redirects to a temporary local loopback web server running on http://localhost:[port] on your PC to complete the handshake.
  • Local Token File: The generated OAuth access and refresh tokens are serialized into token.json located strictly in your local app directory.
  • No Cloud Interception: Our servers never receive, log, or store your Google password, client secrets, access tokens, or Drive file contents.

3. Why Google Workspace Permissions are Requested

OAuth Scope Purpose in G-Stack Studio
https://www.googleapis.com/auth/drive Required to create project root hubs, organize 13 subfolders, upload file copies (PDF/ODT/PPTX), set public sharing permissions, and publish files to the web.
https://www.googleapis.com/auth/documents Required to create keyword-optimized Google Docs articles, inject headings, apply paragraph formatting, and embed interlinking anchor tags.
https://www.googleapis.com/auth/spreadsheets Required to generate Master Keyword Directories, tabulate NAP citations, record public URLs, and format client delivery spreadsheets.
https://www.googleapis.com/auth/calendar & calendar.events Required to generate public entity calendars and schedule geotagged business appointment events with driving citations.

4. Machine Fingerprinting & License Caching

To prevent software piracy while enabling instant offline launching, G-Stack Studio uses ScrapeBox-style machine licensing:

  • Hardware ID (HWID): A non-reversible cryptographic hash combining CPU UUID and Motherboard Serial Number. No personal identifying computer files are read.
  • Cryptographic Cache: Successful validations are cached locally using HMAC-SHA256 signature verification (.license_session.dat) allowing 0.01-second instant offline launch.
  • Machine Transfer Cooldown: Licenses allow 1 free machine transfer every 30 days to protect against shared key abuse.
